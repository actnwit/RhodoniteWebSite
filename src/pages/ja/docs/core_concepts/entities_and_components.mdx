RhodoniteではUnityやUnreal Engineでも見られる、コンポーネントシステムを採用しています。
３D空間上のオブジェクトを意味するEntityに１つ以上のコンポーネントを搭載させることで、そのEntityは搭載したコンポーネントの機能を獲得します。

## Entityについて

エンティティ（Entity）は3D空間上のオブジェクトに相当するものです。Entityそのものは自身のIDを持つだけの入れ物に過ぎません。
このEntityにさまざまな機能を持ったコンポーネント（Component）を追加することで、そのEntityは3D空間上でそれらの機能を発揮します。

Entityを作るには次のようにします。

```ts
const engine = await Rn.Engine.init({
  approach: Rn.ProcessApproach.WebGL2,
  canvas: document.getElementById('world')
});
const entityRepository = engine.entityRepository;
const entity = entityRepository.createEntity();
```

Entityにコンポーネントを追加するには、次のようにします。

```ts
  const entityAddedComponent = entityRepository.addComponentToEntity(
    Rn.TransformComponent,
    entity
  );
```

実際には、Componentを搭載済みのEntityを返してくれる`createXXXEntity`メソッド群を使うことになるでしょう。

```ts
const groupEntity = Rn.createGroupEntity(engine); // TransformComponent, SceneGraphComponentを持つ
const meshEntity = Rn.createMeshEntity(engine); // TransformComponent, SceneGraphComponent, MeshComponent, MeshRendererComponentを持つ
```

## 代表的なコンポーネント

代表的なコンポーネントを紹介します。

### Transformコンポーネント

ローカルの位置（localPosition）、回転（localEulerAngles / localRotation）、スケール（localScale）の設定値を元に、物体の姿勢を示す変換行列を内部的に生成するコンポーネントです。3D空間上に配置するEntityであれば必須のコンポーネントです。

```typescript
const cubeTransformComponent = cubeEntity.getTransform();
cubeTransformComponent.localPosition = Rn.Vector3.fromCopy3(0, 3, 0);
cubeTransformComponent.localEulerAngles = Rn.Vector3.fromCopy3(Math.PI / 2, 0, 0); // ラジアン
cubeTransformComponent.localScale = Rn.Vector3.fromCopy3(2, 2, 2);
```

### SceneGraphコンポーネント

物体の親子関係（シーングラフ）を形成するコンポーネントです。Transformコンポーネントが持つ姿勢の変換行列を積算してワールド行列を生成します。こちらも、3D空間上に配置するEntityであれば必須のコンポーネントです。

```typescript
const groupEntity = Rn.createGroupEntity(engine);
const cubeEntity = Rn.MeshHelper.createCube(engine);
const groupSceneGraphComponent = groupEntity.getSceneGraph();
groupSceneGraphComponent.addChild(cubeEntity.getSceneGraph());
```

### Meshコンポーネント

ポリゴンメッシュのデータを保持するコンポーネントです。

### MeshRendererコンポーネント

Meshコンポーネントからメッシュデータを受け取り、WebGLなどの３DAPIを用いてメッシュの描画を行うコンポーネントです。

### Skeletalコンポーネント

スキニング処理を行うコンポーネントです。

### Cameraコンポーネント

カメラの機能を担うコンポーネントです。

### Lightコンポーネント

ライトの機能を担うコンポーネントです。現在はポイントライト、ディレクショナルライト、スポットライトをサポートします。
Clustered Forwardレンダリング（デフォルトで有効）により、大量のポイントライトやスポットライトを効率的に扱えます。

### Effekseerコンポーネント

オープンソースエフェクトツール`Effekseer`のエフェクトを再生するためのコンポーネントです。WebGL2とWebGPUの両方で動作します。

### その他のコンポーネント

| コンポーネント | 役割 |
|:-----------|------------|
| CameraController | カメラの操作（Orbit / WalkThrough） |
| Animation | キーフレームアニメーションの再生（glTFのアニメーションなど） |
| AnimationState | アニメーションのブレンドやトラック遷移の管理 |
| BlendShape | モーフターゲット（ブレンドシェイプ）による変形 |
| Vrm | VRMの表情とそのブレンドシェイプの管理 |
| Constraint | VRMのコンストレイント |
| Physics | 物理シミュレーション（Rapier） |
| CharacterController | 物理ベースのキャラクター移動 |
| Shape | 軽量な解析的形状（コリジョン形状など） |
| Trigger | 物理センサーで構成されるトリガー領域（enter / stay / exit イベント） |
| Raymarching | レイマーチング用のエンティティ |

### コンポーネントの処理の流れ

#### 処理の起点

Rhodoniteでは、まず`Rn.Engine.init`でEngineインスタンスを生成して、次にExpressionを構築、最後に`engine.process`メソッドにエクスプレッションの配列を指定して処理を開始します。
（すべてのEntityを単に描画したいだけであれば、代わりに`engine.processAuto()`を使うこともできます。）

```ts
// Initializes Rhodonite
const engine = await Rn.Engine.init({
  approach: Rn.ProcessApproach.WebGL2,
  canvas: document.getElementById('world')
});

// constructs expressions
...

// drawing
engine.startRenderLoop(()=>{
  engine.process([expression]);
});
```

つまり、基本的には各描画フレームで１度呼ばれる`engine.process`メソッドが、処理の起点になるわけです。

#### データの階層

##### Frame, Expression, RenderPass
フレーム(Frame)は１フレーム分の描画情報を持っており、具体的には内部にエクスプレッション（Expression）の配列を持ちます。エクスプレッションは複数のレンダーパス（RenderPass）を配列として保持しています。レンダーパスには、処理に対象となるEntity群を指定することができます。そして、各Entityは複数のComponentを持っています。
次のようなイメージです。

- フレーム
  - エクスプレッションの配列
    - エクスプレッション1
    - エクスプレッション2
      - レンダーパスの配列
        - レンダーパス1
        - レンダーパス2
          - Entity1
          - Entity2
          - Entity3
            - TransformComponent
            - SceneGraphComponent
            - MeshComponent
            - ...
          - ...
        - ...
    - ...

さらに、コンポーネントは「処理のステージ」という概念を持っています。以下のステージです。

- ProcessStage.Load
- ProcessStage.Logic
- ProcessStage.Render

（`ProcessStage`列挙には`Create`、`Mount`、`PreRender`、`Unmount`、`Discard`も定義されていますが、現在エンジンが実行するのは上記の3つのステージです。）

基本的には、各コンポーネントにおいて、上から下にむかって処理のステージが遷移していきます。
一度に複数のステージに所属することはなく、各Componentは常にどれかのステージだけを処理しています（ステージの遷移には`moveStageTo`メソッドを使います）。
各Componentには、それぞれのステージと対応する名前のメソッドを持っています。
例えば、`ProcessStage.Logic`に対応するコンポーネントのメソッドは`$logic`メソッドになります。
Logicステージでは、現在Logicステージにいるコンポーネントの`$logic`メソッドが実行されることになります。


### 実際の処理工程

データの階層について説明しましたが、実際の実行順序がこのデータ階層の上から下に、と単純になっているいうわけではありません。
実際に`engine.process`メソッドの中身（WebGL2の場合を簡略化したもの）を見てみると、次のようなループ構造になっています。

```typescript
  // Engine.process の簡略版（WebGL2の場合）
  for (const stage of Component._processStages) { // Load, Logic, Render
    const commonMethodName = `common_${stage.methodName}`;

    if (stage === ProcessStage.Render) {
      // 描画前にライトクラスタ（Clustered Forward）とGPUデータを更新
      this.__lightClusterSystem.update(expressions);
      MeshRendererComponent.common_$prerender(this);

      // エクスプレッションの配列でループ処理を実行
      for (const exp of expressions) {
        // 描画系コンポーネント（MeshRenderer, Effekseerなど）の種類順にループ処理を実行
        for (const componentTid of renderingComponentTids) {
          const componentClass = ComponentRepository.getComponentClass(componentTid)!;
          // エクスプレッションが持つレンダーパスの配列でループ処理を実行
          for (const renderPass of exp.renderPasses) {
            renderPass.doPreRender();
            this.bindFramebufferWebGL(renderPass);
            this.setViewportForNormalRendering(renderPass);
            if (componentTid === WellKnownComponentTIDs.MeshRendererComponentTID) {
              this.__cgApiResourceRepository.clearFrameBuffer(this, renderPass);
            }

            // このレンダーパスで描画するプリミティブをソート（不透明、半透明など）
            const primitiveUids = MeshRendererComponent.sort_$render(this, renderPass);
            // 描画する
            componentClass[commonMethodName]({ renderPass, primitiveUids, processStage: stage, engine: this, ... });

            // Resolveフレームバッファが設定されていればMSAAのResolveを行う
            renderPass._copyFramebufferToResolveFramebuffersWebGL();
            renderPass.doPostRender();
          }
        }
      }
    } else {
      // LoadステージとLogicステージ（Transform、カメラ、ライト、アニメーションなどに変化がなければスキップ）
      // コンポーネントの種類順にループ処理を実行
      for (const componentTid of componentTids) {
        const componentClass = ComponentRepository.getComponentClass(componentTid)!;
        // その種類のコンポーネント全てに共通する処理
        componentClass[commonMethodName]?.({ processStage: stage, engine: this, ... });
        // 現在のステージにいる各コンポーネントの対応メソッド（$load / $logic）を実行
        Component.process(this, componentClass, stage);
      }
    }
  }
```

簡略化して箇条書きすると、以下のような流れでループ処理が回っていきます。

- 「処理のステージ」の種類の順にループを実行（Load → Logic → Render）
  - LoadステージとLogicステージでは
    - コンポーネントの種類順にループ処理を実行
      - その種類のコンポーネント全てに共通する処理をする
      - 現在のステージにいる各コンポーネントについて、そのステージに対応するメソッドを実行する
  - Renderステージでは
    - エクスプレッションの配列でループ処理を実行
      - 描画系コンポーネントの種類順にループ処理を実行
        - エクスプレッションが持つレンダーパスの配列でループ処理を実行
          - レンダーパスで描画するプリミティブをソートして描画する

端的にいえば、LoadやLogic、Renderといった「処理のステージ」が一番大きな処理の段階です。
それぞれの処理のステージにおいて、さらにコンポーネント単位で処理が行われ、そのコンポーネントの処理では、そのコンポーネントを所持しているEntityの数だけ、コンポーネントインスタンスが一気に流れるように大量処理されることになります。
